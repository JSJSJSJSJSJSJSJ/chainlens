# 研究方法、时间语义与评分

研究信息截止日固定为 **2026-09-16**。该日期表示资料允许的最晚发表日期，不代表已完整搜索截至当天的所有披露。此数据集是精选的可追溯样本，不能据此断言关系不存在、仍在持续或对营收贡献大小。

## 来源与研究步骤

1. **发现**：用检索工具寻找监管文件、公司年报、投资者关系公告、官方产品或合作声明。搜索摘要仅为线索。
2. **获取**：打开原文，记录实际 `retrieved_at`。不绕过登录、robots、验证码、付费墙或限流；不可访问则记录缺口。
3. **整理**：以可定位章节或段落摘录简短原文，另写中文解释。发布日期未知使用 null；不得从 URL 或检索时间推测。
4. **去重**：同一公告转载不构成独立支持；独立来源标识追踪信息来源而不是网页数量。同一发行人的多次公告也不自动获得跨来源加分。
5. **核验与判断**：检查实体、业务、方向、有效时间、支持/反驳立场，注明推断和未知部分。工具辅助阅读不等同于项目作者人工复核。
6. **评分**：后端按规则版本计算；前端只展示。金额作为上下文，不作为必需的可信度条件。
7. **导入**：校验快照、引用和摘录 SHA-256，事务写入；同一版本重复导入保持幂等。
8. **查询**：网页、HTTP API、CLI 共用后端逻辑，安装后查询不访问互联网。

资料记录见 [research-log.md](research-log.md)。来源全集可用 `uv run python scripts/snapshots.py sources` 输出。仓库不默认再分发原文全文；原始来源的权利不由本仓库 Apache 代码许可证授予。保存的摘录只用于核查，具体访问、许可和再分发限制逐条记录；许可未知时明确写未知。

## 关系判定与实体消歧

| 类型 | 内部方向 | 判定边界 |
| --- | --- | --- |
| supplier | 供应方 → 采购方 | 明确供货/采购披露；产品使用或生态兼容不自动证明直接采购 |
| customer | supplier 边的相对角色 | 查询供应方时，另一端显示客户；不是重复存储的边 |
| partner | 对称 | 明确合作声明，并限定合作内容；不推导交易规模 |
| investor_or_investee | 投资方 → 被投资方 | 有日期的历史投资/持股事实；不能自动推出当前持股 |
| peer | 对称 | 明示比较业务维度、产品竞争依据；不是新闻中共同出现 |

稳定公司 ID 与证券标识分开；同名实体按法律主体、官方身份描述与交易所核对。若事实主体为上市公司子公司，在实体说明和关系描述中写明，`entity_resolution=mapped` 会影响评分。别名仅供检索，不能单凭相同关键词合并两个实体。

`confirmed` 表示证据直接支持所写的有限结论；`inferred` 是有依据但不是直接披露的推断；`unknown` 为不足以确定。`human_review_status` 与三者独立：`pending` 表示待人工复核，`review_prepared` 表示审核记录草稿已准备、待本人确认，均不表示人工通过；`approved`表示人工审核通过，当前v3的22条关系由JOE于2026-09-22确认，逐条判断见[human-review.md](human-review.md)。即使 confirmed 得到高分，仍可能是待人工复核的历史事件。

## 三种时间与两种过滤

- `published_at`：证据发表日；未知为 null。
- `valid_from` / `valid_to`：结论成立的事件日或区间边界；并非网页发布时间的机械复制。
- `retrieved_at`：实际读取资料的 UTC 时间。后来取得的旧公告只说明其当时公开，不能表示当时已完成核验。

`known_at=YYYY-MM-DD` 是**当时公开信息视角**：只保留发布日期已知且不晚于该日的证据，至少有一个这样的支持证据才显示关系，依据该子集重评分。未知发布日期不会因为勾选未知有效时间而纳入。此视角不是历史审计日志，研究结论仍由本次研究形成。

`valid_at=YYYY-MM-DD` 是**关系有效时间视角**：已知起点不晚于当日、已知终点不早于当日；开放终点只有持续状态为 current 且未越过截止日才明确覆盖。历史单次事件可用相同起止日期表示。明确不在范围内的关系不会被“包含未知时间”重新纳入。

`include_unknown_time=true` 仅允许有效时间边界不足的关系作为不确定候选出现，不能把它们称为当日确定有效。known_at 与 valid_at 可组合。所有查询日期不得超过研究截止日，非法日期与超界参数返回 422。

历史公告证明历史事实；没有持续性核验时 `temporal_status=historical/unknown`，`continuity_note` 说明限制。当前有效性单独输出为 supported / historical_only / unestablished。

## 评分规则 v1.0.0

分数是规则评估值，**不是业务重要性、投资价值或统计校准概率**。直接性、来源和独立性根据支持证据计算；冲突证据单独扣分。

| 分项 | 满分 | 意义 |
| --- | ---: | --- |
| 直接证据 | 30 | 来源是否直接支持这条具体结论 |
| 来源可信度 | 25 | 监管、当事公司和媒体的来源层级 |
| 来源独立性 | 10 | 信息来源而非转载数量 |
| 时间明确度 | 10 | 日期、时间支持和相对评估日的新旧程度 |
| 实体身份 | 10 | 精确主体、可说明的母子映射或仍有歧义 |
| 关系判定 | 15 | 具体类型所需依据是否具备，同行是否有比较维度 |
| 来源冲突 | 0 | 每个独立反驳来源扣 30 分 |

总分限制在 0–100。推断结论上限 69，unknown 上限 39。每个独立反驳来源扣30，最多扣60。直接支持30分，只有间接支持12分；来源最高取监管25/公司22/媒体12；独立支持来源每组5分，最多10；实体 exact/mapped/uncertain 为10/6/0；已确认且直接支持的类型判定15分，只有其他支持7分。

历史事实的时间分为有事件边界且有发布日期10分、只有发布日期5分、无发布日期0分。非历史结论根据最新支持证据相对研究截止日的新旧，365天内10分、730天内7分、更早3分；缺少事件边界再减5分，最低0分。当前持续性 supported 还要求 current 标注、明确起点、最近730天内直接支持且无冲突；730天是版本化启发式规则，不是合同有效期的证据。

具体运行输出以 `backend/app/services/scoring.py` 和对应测试为准；接口返回每个分项的实际分值、上限、理由、规则版本和计算时间，不隐藏截断。默认快照分数导入时持久化；known_at 子集在查询时计算并返回实际计算时间，数值和理由确定，时间戳随执行改变。如果只有较早间接依据，原 confirmed 结论降为 inferred 候选，并明确区分完整快照原结论，避免把后来的直接披露显示为当时已确认事实。

真实样例：TSMC 供货90分（30+25+5+5+10+15），有效区间未知，所以不声称当前持续；Micron 供货95分，因为另一来源提供间接补充，独立性项增加5分；CoreWeave 投资95分，有明确历史交易日，但 current_validity 为 historical_only；ASUS 历史采购82分，因为来源为公司年报22分且发布日期未知0分。金额缺失不会使上述供货结论失信。

时效性针对结论语义处理：较早但有明确日期的历史事件仍可能可信，不能仅因年限长就否定历史投资事实。与此同时，这种高分绝不证明当前持股或当前合作持续。没有金额不会扣分；若有数量或金额，保存在 quantitative_context，并保留其统计范围和日期。

真实数据不人为制造互相矛盾的证据。冲突、转载和未知日期等边界通过明确隔离的合成测试验证；正式快照里没有出现某类异常，不表示系统已从现实中发现该异常。

## 更新与回溯

在线更新是独立的研究操作，不随服务启动执行：先列出来源清单，重新打开允许访问的原文，追加新证据并记录新的实际获取时间和研究判断。在 `data/snapshots/` 创建新的版本文件，**不要覆盖已发布的旧快照**。新资料晚于本次截止日时，应建立不同截止日的数据集，不混入本快照。

使用 `uv run python scripts/seal_snapshot.py NEW.json --manifest NEW.manifest.json` 为候选更新摘录的 UTF-8 SHA-256，并在完整结构校验后生成 manifest；该工具不会进行来源核验，也不会修改人工复核状态或读取日期。以 `scripts/snapshots.py compare OLD NEW` 检查新增、删除、修改的稳定 ID，再通过 `uv run chainlens import-snapshot --path NEW.json` 显式导入。文件 SHA-256 校验是字节级校验，换行和序列化变动也会改变摘要；`.gitattributes` 为 JSON 固定 LF。

回溯时将指定快照导入独立 SQLite 路径，保留原库即可并排比较。manifest 校验防意外变更，不是来源内容的签名或版权许可证明；摘录摘要只覆盖保存的摘录，不冒充远程全文摘要。
