# 五分钟演示与面试讲解

## 演示路径

**0:00–0:40** 打开工作台。从 NVIDIA 的证券身份、截止日和“待人工复核”说明开始，解释目标：让具体关系可以追溯，而不是展示一张缺少证据的公司网络。

**0:40–1:40** 筛选供应商，打开 TSMC 的供货关系。指出两端身份、供应方到采购方的方向、公告定位和原始链接。再看同一公司合作关系，说明一个公司对可以有多条具体业务关系。

**1:40–2:30** 打开投资关系，展示历史事件日期、金额上下文、持续性限制和评分分项。说明“这个投资事件可靠”与“今天仍持有这些股份”是两个问题。

**2:30–3:15** 切换到关系图，使用同一筛选并点击边，看到同一详情面板。加入时间过滤或提高最低分，演示空结果和重置。

**3:15–4:15** 展示 API `/docs` 和 CLI JSON。用相同筛选查询，并解释后端共用服务保证角色、评分、排序和时间语义一致。

**4:15–5:00** 展示快照、manifest、后端测试和真实后端 E2E 结果。诚实说明人工复核、资料覆盖和公开发布的剩余步骤。

演示前按 README 启动两端。浏览器核心流程使用本地数据，不依赖当天外网是否能打开来源；原文链接用于复核，不是页面正常加载的前置条件。

## React 可以怎样讲

你有 Vue 背景，可以先用“受控表单 + 单向数据流”的方式解释。筛选控件的值来自页面 state，用户操作调用回调更新 state；列表和图接收相同条件。props 明确组件需要什么，避免引入全局状态管理器增加学习成本。

`useResource` 是封装请求生命周期的 Hook：根据 URL 发请求，返回 data/loading/error，清理时调用 AbortController 并设置 active guard。既停止不再需要的网络请求，也阻止已完成但过期的结果覆盖新筛选。依赖数组描述何时重新同步外部资源。

选中关系 ID 属于工作台状态。表格和图只负责触发同一个选择动作，详情组件根据 ID 请求后端结论和证据。详情评分不在客户端重新计算，从而避免列表、图、CLI出现三个不一致的分数。

TypeScript 描述接口和组件边界，但不等于运行时数据验证；后端 Pydantic 提供真正的输入校验。加载、错误与空结果是不同状态，不能都用“没有数据”表达。键盘按钮、表单 label、可见状态文本和响应式布局是基础可用性的一部分。

## 常见追问

| 问题 | 可以给出的回答 |
| --- | --- |
| 为什么选 SQLite？ | 研究快照规模小、读多写少、本地可复制；减少部署依赖。增长后可迁移 PostgreSQL，但先保留明确查询契约。 |
| 为什么不是自动爬虫加大模型？ | 难点在主体、时间和关系语义，抓到文本不等于事实成立。先建立可复核的数据边界，更新作为独立研究流程。 |
| 置信度 90 是否代表 90% 正确？ | 不是。它是确定性规则分数，分项可解释，没有做统计概率校准。 |
| 没有金额为什么还能得高分？ | 明确的合作或供货披露足以支持关系存在；金额衡量规模，不能与关系可信度混为一谈。 |
| 多个媒体转载会提分吗？ | 不会，独立性按信息来源标识去重，不是 URL 数量。 |
| 为什么都是待人工复核？ | AI 和工具可以辅助核查，但不能代替作者签署审核；事实状态和审核流程独立。 |
| 如何处理矛盾？ | 支持和反驳保存在关系与证据的关联上，反驳按独立来源扣分，理由可见，不覆盖掉原始证据。 |
| 用过 GPU 就算客户吗？ | 不能，可能由 OEM 或云提供商间接取得。只有明确采购/供货依据才能建立对应结论。 |
| 旧投资记录为什么不删除？ | 历史事件仍有研究价值；保存事件有效时间并明确不能代表当前持股。 |
| 怎么保证可复现？ | 锁文件、版本化快照、字节与摘录摘要、幂等导入、共享业务服务及离线测试。 |
| 下一步改进什么？ | 先人工核验、补独立证据和近期客户披露；再考虑数据库迁移、后台复核工作流与更完整可访问性测试。 |

不要声称这是生产证券研究平台、已穷尽 NVIDIA 供应链，或自动知道当前所有合作关系。项目价值在于对有限结论给出清楚且可运行的证据链。
